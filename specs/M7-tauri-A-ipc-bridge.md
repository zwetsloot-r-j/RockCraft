# M7-tauri-A-ipc-bridge — Composer state, run_action/query commands, typed TS bindings

> Milestone: M7 · Issue: #161 · Suggested tier: opus
> Branch: `claude/tauri-ipc-bridge`
> Depends on: M2-tauri-scaffold (#22, merged), M7-tauri-0-solid-swap (#171 —
> the frontend is SolidJS)

## Goal

Give the Tauri app a live `rockcraft-core` brain: the backend owns a
`Composer`, the webview drives it through invoke commands that mirror the
WebSocket control protocol, and state flows back as events. Every later Tauri
screen (edit, play, record, library) builds on this bridge — it is the M4
(action model + control server) of the Tauri track.

## Context

- `crates/core/src/action.rs` — `Action` (45 variants), `Effect`
  (`AuditionNote { pitch, velocity }`, `AuditionChord { pitches }`, `AllOff`),
  `action_from_name(name, &serde_json::Value)`, `action_help()` (names +
  param schema + descriptions). All serde-serializable already.
- `crates/core/src/composer.rs` — `Composer::{new, from_timeline, apply,
  advance, ingest, leave, snapshot}`; `ComposerSnapshot` (notes, cursor, bpm,
  time_sig, subdivision, input_mode, playing, playhead_us, looping,
  loop_start_us, loop_end_us, metronome, selection, chord_preview,
  clipboard_len, backing_offset_us) — derives `Serialize`.
- `crates/control/src/` — the WebSocket server's `protocol.rs`/`command.rs`
  show the exact request/response shapes to mirror; do **not** depend on the
  control crate, just keep the vocabulary identical (snake_case action names,
  `State`/`Actions`/`Help` query kinds).
- `tauri-app/src-tauri/src/lib.rs` — currently a bare scaffold (no commands).

## What to do

### Backend (`tauri-app/src-tauri/src/`)

```rust
// state.rs
pub struct AppState {
    pub composer: Mutex<Composer>,
}
```

Commands (register with `.manage(AppState…)` + `.invoke_handler(…)`):

```rust
#[tauri::command]
fn run_action(state: State<AppState>, name: String, params: serde_json::Value)
    -> Result<ActionReply, String>;
// action_from_name → composer.apply → ActionReply { effects, snapshot }
// ActionError maps to Err(err.to_string())

#[tauri::command]
fn query_state(state: State<AppState>) -> ComposerSnapshot;

#[tauri::command]
fn query_help() -> serde_json::Value;  // serialized action_help()
```

Tick loop: spawn a thread (in `setup`) that every ~4 ms locks the composer,
calls `advance(dt_us)` with measured wall-clock delta **only while
`is_playing()`**, and — when the snapshot changed or effects were produced —
emits to the webview:

- event `"snapshot"` payload `ComposerSnapshot`
- event `"effects"` payload `Vec<Effect>`

`run_action` also emits both events after applying, so the UI never polls.
Keep the lock scope tight (lock, mutate, clone payloads, unlock, then emit).

### Frontend (`tauri-app/src/ipc/`)

```
ipc/
  types.ts    # ComposerSnapshot, NoteView, Cursor, TimeSig, Subdivision,
              # InputMode, SelectionView, Effect — field-for-field mirrors
  bridge.ts   # runAction(name, params?), queryState(), queryHelp(),
              # onSnapshot(cb), onEffects(cb)  (listen() wrappers)
```

`runAction` is `invoke("run_action", { name, params: params ?? {} })`. Type
the action names as a string-literal union generated by hand from
`action_help()` output (45 names) — a comment must point at
`crates/core/src/action.rs` as the source of truth.

### Demo wiring

Add a temporary debug strip to `App.tsx` (kept until the edit screen lands):
buttons for `add_note` / `cursor_right` / `undo` and a `<pre>` of the latest
snapshot. This proves the round trip in `npm run dev`.

## Tests

Rust unit tests in `src-tauri` (no window, test the functions the commands
delegate to — factor command bodies so they take `&AppState` directly):

- `run_action("add_note", {})` → snapshot gains one note at the cursor.
- `run_action("resize_note", {"delta_steps": 2})` after add → duration grows.
- Unknown action name → `Err` containing `unknown action`.
- Tick-advance with `playing == true` moves `playhead_us`; with `false` it
  does not (call the advance helper directly with a fixed `dt_us`).

TypeScript: `npx tsc --noEmit` (strict) covers the type mirrors.

## Scope boundaries (do NOT)

- Do not add screens or visual changes beyond the debug strip.
- Do not start audio (`crates/audio`) or MIDI (`crates/midi`) — effects are
  emitted, not yet sounded (#166/#167).
- Do not depend on `rockcraft-control`; mirror its vocabulary only.
- Do not add frontend state libraries — Solid's own `createSignal`/
  `createStore` + event listeners (per `tauri-app/CONVENTIONS.md`). The
  snapshot mirror is a `createStore` updated from the `snapshot` event.
